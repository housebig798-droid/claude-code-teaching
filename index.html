# Claude Code 教學課綱｜老闆＆會計師專班 **工具環境**：Claude Code（於 Warp 終端機中操作） **對象**：非技術背景之企業負責人與會計師 **形式**：共三堂課，每堂建議搭配實機操作 --- ## 第一堂｜認識工具、安裝設定 | 項目 | 內容 | |---|---| | **目標** | 確認學習動機與用途、完成安裝、建立基本認識 | | **開場：了解用途與動機** | 詢問兩個問題：①想用 Claude Code 做什麼（做工具、抓資料、寫自動化腳本、產報表…）②期待的操作方式（自己打指令 / 口頭描述需求讓它做） | | **簡介：從 Cowork 到 Code** | 說明 Claude Cowork（非技術知識工作用）與 Claude Code（終端機、程式導向）的差異，讓學員理解為什麼選擇 Code、以及它跟一般聊天 AI 的不同：不是「問答」，是「描述目標→它規劃→執行→你確認」的協作模式 | | **安裝流程** | 1. 先安裝 Warp 終端機 2. 再安裝 Claude Code CLI，Warp 會自動偵測並接管介面（不需另外設定）3. 驗證是否能在 Warp 中成功呼叫 `claude` | | **疑難排解附錄** | PATH／環境變數問題整理：Windows 需在「環境變數」設定中確認 npm 全域路徑是否已加入 `Path`；Mac 需確認 shell 設定檔已生效。附上你自己實測過的具體修正步驟，並註明是否需要重開機／重開終端機 | | **Warp 兩個模式要先釐清** | Warp 自己也有一套內建 agent（Oz），跟 Claude Code 是兩回事。建議課前把 **Settings > Features > General > Default mode for new sessions** 設成 **Terminal**，讓新分頁預設是乾淨終端機，直接打 `claude` 指令即可，不用碰到 Warp 自己的 Agent Mode。若不小心進入 Agent 對話畫面，用 `⌘I`（Mac）／`Ctrl+I`（Win/Linux）切回終端機模式再打 `claude` | | **驗收** | 學員能自行在 Warp 中打開 Claude Code 並成功對話 | --- ## 第二堂｜小案子實作＋核心機制體驗 | 項目 | 內容 | |---|---| | **目標** | 透過一個小任務，讓學員熟悉下指令、權限確認、記憶機制三件事 | | **小任務設計** | 依第一堂了解到的用途，設計一個貼近工作情境的小案子（例如：整理一批 CSV/發票資料、產出簡易對帳報表），讓學員 DIY 操作一輪 | | **練習重點①：下指令的方式** | 示範用 Warp 的 `Ctrl+G` 多行輸入編輯器，把需求分段寫清楚，降低「擠成一行」的困難 | | **練習重點②：權限確認的過程＋通知設定** | 故意設計會觸發權限詢問的動作（如刪除檔案、執行系統指令），讓學員親眼看到 Claude Code 何時會停下來等待確認。順便設定 Agent 通知：第一次跑 `claude` 時 Warp 會跳出一鍵安裝通知外掛的提示，點下去即可；若沒跳出，可在 Claude Code 內手動執行 `/plugin marketplace add warpdotdev/claude-code-warp` 及 `/plugin install warp@claude-code-warp`（需先裝好 `jq`），裝完重啟或 `/reload-plugins` 生效。之後 Claude 需要確認權限或做完任務都會跳通知，不用一直盯著螢幕 | | **練習重點②-2：Code Review 面板** | 示範 `⌘⇧+`（Mac）／`Ctrl+Shift++`（Win/Linux）打開 code review 面板，直接在畫面上看 Claude 改了什麼，並在特定行留言送回給 Claude 修正，不需自己讀 diff 語法或複製貼回終端機 | | **練習重點③：CLAUDE.md vs Auto Memory（重要釐清）** | - **CLAUDE.md**：人工撰寫的規則檔案，可用 `/init` 自動產生初稿（約 80% 完成度），但仍需人工檢查/調整，適合放固定規則（報表格式、命名慣例、禁碰資料夾）
- **Auto Memory**：真正「不需人工維護」的機制，Claude 會自動記住你糾正過的錯誤與偏好，之後對話自動套用。示範方式：故意讓它做錯一次→糾正→開新對話問類似問題→讓學員看到它記住了 | | **練習重點④：接續上次對話** | 示範 `claude --continue`（或 `-c`）直接接續最近一次對話，不用選；進階可提 `claude --resume`（或 `-r`）跳出對話列表讓你挑選要接續哪個專案。建議先教 `--continue` 就好，符合「不用每次重新解釋」的需求 | | **驗收** | 學員能獨立完成一次「下指令→確認權限→看到記憶生效→關掉再接續對話」的完整流程 | --- ## 第三堂｜真實案例實戰＋收尾 | 項目 | 內容 | |---|---| | **目標** | 讓學員獨立完成一個較完整的真實任務，並建立長期安全使用的習慣 | | **前半段：實戰演練** | 使用去識別化的真實資料（對帳單、發票、報價單），由老闆或會計師主導，從頭到尾自己下指令完成一個小專案；你僅在卡關時介入。目的是驗收前兩堂內化程度，並讓成果具體可見 | | **後半段：風險與長期使用習慣** | - 哪些情況一定要人工確認（送出、刪除、碰觸客戶/財務敏感資料）
- 絕不能讓 Claude Code 接觸的資訊：密碼、帳密、稅務 ID 等
- 如何保存已完成的腳本／流程，下次直接重複使用，不必每次重新解釋
- 常見指令錯誤示範：需求描述太模糊會發生什麼問題 | | **收尾** | Q&A，並收集學員接下來想自動化的任務清單，作為課後的自主練習路線圖 | | **驗收** | 學員手上有一個親手完成的實際成果，並清楚知道之後可以安全地繼續使用 | --- ## 給講師（你）的課前準備清單 - [ ] 自己完整跑過一次「丟檔案→下指令→確認權限→輸出結果」流程 - [ ] 記錄清楚 PATH／環境變數的修正步驟（含作業系統差異） - [ ] 練習 `/init` 產生 CLAUDE.md 草稿，並手動調整過一次 - [ ] 實測過 Auto Memory 的記憶與呼叫效果 - [ ] 熟悉 Warp 的 `Ctrl+G` 輸入編輯器、通知功能、Code Review 面板 - [ ] 準備第二、三堂的示範資料（建議先用去識別化假資料測試過一輪）
